# Markdown and reader migration audit — September 8, 2026

The breast-sensation source link failed in the shared Obsidian-to-Markdown converter. The source wikilink and destination heading exist. The converter left spaces in the fragment, producing literal Markdown instead of an anchor. It also failed to convert the heading name to the ID generated by the reader.

This repair is based on `origin/main` at `c8e306e2` in the isolated `codex/markdown-migration-fixes` worktree. It has not been deployed. Unrelated work in the primary checkout is untouched.

## Findings and repairs

| Finding | Result |
| --- | --- |
| Wikilink heading fragments retained spaces and capitalization | Normalize fragments with the same GitHub slugger used for rendered heading IDs; encode Unicode safely. |
| Fragment-only wikilinks such as `[[#Local Heading]]` pointed at the homepage | Preserve a fragment-only URL so navigation stays on the current document. |
| Initial HTML heading IDs differed from React for entities and inline code | Generate IDs from decoded HTML text nodes, matching `rehype-slug`, including duplicate heading suffixes. |
| PDF wikilinks with `#page=3` or uppercase `.PDF` lost their relative directory | Identify the file before processing its fragment and extension; retain the PDF page fragment. |
| Encoded Markdown asset names were double-encoded; HTML entities could become filename bytes | Decode the URL once, then encode the file API query. Decode HTML attributes before URL resolution. Preserve literal percent sequences with exactly one decode. |
| Server-rendered assets on a root page incorrectly acquired an `index/` directory | Use the shared image/link resolver for server HTML and React. |
| PDF chips included `#page=3` in the filename, and malformed percent escapes could throw | Separate filenames from URL fragments, tolerate malformed escapes, and escape filename text. |
| Unbalanced parentheses in wikilink page names broke generated Markdown | Percent-encode route parentheses. |

The raw-fragment regression is traceable to `1b88b4b0`, which introduced `wikiRouteHref` while preserving raw query/fragment suffixes. The initial-HTML heading mismatch is a divergence in the newer HTML-first rendering path. The other defects were also present at the release baseline; this audit does not claim they were all introduced by the migration.

## Coverage

A new shared set of contracts exercises four entry points: server Markdown, React Markdown, initial HTML, and streamed HTML. Prior renderer-parity tests compared only the server and React paths. Expectations cover actual destinations and heading IDs, not merely agreement between implementations.

- The new matrix passes **76/76** checks. The same test file on unchanged `c8e306e2` fails **52/76**, confirming that the tests observe the repairs.
- Focused rendering, initial-HTML, cache and streaming unit tests pass **133/133** checks.
- Production build, app and Markdown typechecks, focused ESLint, bundle budgets, and whitespace checks pass.
- **33 initial-HTML browser checks and 11 heading-navigation checks pass** against the production build with synthetic local documents, including the reported cross-page heading form, same-page jumps, initial-HTML handoff, delayed scripts, desktop/mobile layouts, and existing navigation contracts.

The combined browser run initially caught a subpixel-sensitive assertion in the new same-page test: the heading was visible but its top settled 1.375 pixels above the pane edge. The test now checks 95% heading visibility; the entire 11-test heading suite was rerun successfully.

The initial HTML renderer's conservative sanitizer and deferred rich widgets remain intentional differences. This is an audit of Markdown destinations, heading identity, assets, and reader handoff, not a certification of every migrated feature or clinical page.

## Corpus scan and remaining issues

A read-only scan of non-hidden Markdown files in the Diana vault found **12 wikilinks with spaces in their heading fragments**, **50 encoded local Markdown destinations**, and **500 headings containing an ampersand**. These are candidate counts, not confirmed broken-link counts.

Nine of the twelve heading references resolve to existing headings with the repaired converter, including the reported breast-sensation source link. Two historical meeting-note references name a heading that is no longer present, and one research reference uses a bare local document name. Those three source references are not repaired by fragment normalization. Source documents were not rewritten.

The broader app unit suite is not green. The same two failures reproduce on unchanged `c8e306e2`:

1. `bun test src server scripts convex/lib` also selects `e2e/visual-observer.spec.ts` because `server` matches the filename, causing a Playwright `beforeEach` error in Bun's unit runner.
2. The full-suite bulk-manifest test exhausts SQLite WASM's fixed memory. Its isolated file passes all seven tests. This is a reproducible full-suite issue, not proof of a production memory failure.

These are separate test-infrastructure findings, outside the rendering repair.
