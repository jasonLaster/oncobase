Scope: `e2e/` (73 specs), `parity-e2e/` (13), `production-e2e/` (1), `preview-e2e/` (2), plus five Playwright configs and three CI jobs.

## 2. Findings

**Redundancy**
1. **One concern owns a third of the suite.** ~170 browser tests exercise reader startup states (cached paint before identity, late identity, denial, sign-out, stale manifest, worker failure…). Most are pure state-machine cases ("A + B → C") that need a fake clock and fake store, not a browser. Each takes 45–90s timeouts and heavy route mocking (`fixtures.ts`).
2. **`parity-e2e/` re-runs `e2e/` flows.** Journeys, reader, search, tools, imaging, comments, security all repeat tests that exist in `e2e/` at 3 widths. Its own header and `session-continuity` ("survive a frontend cutover") say it exists to compare the Next → Vite cutover. If the cutover is done, the whole directory plus `compare-parity.ts`, `playwright.parity.config.ts` and the visual-parity "production" comparisons are dead weight.
3. **Auth-gate is tested in 6 places**: `auth-gate-security`, `preview-e2e/auth-gate`, `parity-e2e/security`, `backend-api`, `sidebar-pdfs` ("requires a password gate"), `production-e2e/reader` (first test).
4. **Palette is tested 4×**: `command-palette` (26), `search` local-finder, `parity-e2e/reader`, `production-e2e/reader` — and `command-palette` alone has 4 geometry/typography/theme tests that overlap `visual-parity`.
5. **Responsive matrices**: landing at 3+ widths × 3 tests, sign-in, calculator, pathology, terms, search, comments — each re-asserting "no horizontal overflow". One generic overflow sweep over all public routes replaces ~25 tests.
6. **Multi-site isolation (10 invariants) and `pii-redaction`** each re-check the same backend APIs as `backend-api` (search, tools, downloads, file).
7. **Table expansion**: `table-expansion` (14) + `table-examples` (7) + `table-performance` (3) + parity `tools`; ~8 are CSS-geometry cases (fade edge, resize widths, wheel scroll).
8. **DICOM**: 29 tests, 1.8k lines, serial; ~10 are layout/rail/resizing/mobile variants of the same viewer shell.

**Wrong tier / low value**
- Tests of test instrumentation (`visual-observer`, `visual-runtime`, `paint-monitor`) belong in unit tests (`scripts/test-unit.ts` already references them).
- Performance budgets (`chat-perf`, `table-performance`, `reader-performance`, latency budget in `backend-api`) are timing-flaky in a correctness gate; they belong in the existing `scripts/profile-*.ts` / `chat-bench.ts`.
- `header-shell.spec.ts` is `describe.skip` (dead). `visual-stability-live`, `additive-paint` live probe, `comments-live`, `live-data` are opt-in/never run in CI.
- 7 of 15 `chat-nav-resilience` tests and most of `chat.spec` skip without `AI_GATEWAY_API_KEY` + Convex URL.

**Gaps (more important than the duplicates)**
1. **Every authenticated and role path is skipped in CI.** `wiki-vite-checks.yml` passes no `NEXT_PUBLIC_CONVEX_URL`, `AI_GATEWAY_API_KEY` or Liveblocks key, so `role-based-access`, `tag-page-access`, `admin-access`, `admin-users-bulk`, live chat, `comments-live` all skip. The only CI-run auth coverage is mocked identity. A real sign-in → role-gated page → sign-out journey never runs in CI. *(Verify against actual CI logs; I only read the workflow.)*
2. **Chat has no CI-run end-to-end**: send → stream → persist → reload only exists in parity (needs real model). A recorded/fake model at the API boundary would make it deterministic.
3. **Comments mutations**: create/reply/resolve/delete only in the private live spec; CI covers just the empty state and rail layout.
4. **No sign-out journey** against a real session (only cache-invalidation tests with mocked notifications).
5. **Mermaid/diagram rendering** has one gantt test; no flowchart/sequence render check.
6. **Cross-browser** is a 7-file WebKit subset; Firefox is configured but not run. No iOS-Safari-specific touch checks beyond the DICOM drag test.
7. **Accessibility**: one axe spec (4 pages) and one parity spec; no keyboard-only pass across reader → palette → search → viewer.
8. **Publish → read round trip**: nothing verifies that a vault change published by the pipeline shows up in the reader (fixtures mock the manifest). Highest-value integration seam that the mocks hide.
9. **Admin**: one autosave test and one bulk test, both CI-skipped; no access-rule (path/tag/domain) editing UI test.
10. **Data-loss paths**: annotation save failure is covered for pathology, not DICOM; comment draft loss not covered.

## 3. Proposed suite (~115 tests, ~20% of today's)

Principle: **browser tests assert what a user can do or see; state machines and layout math go to unit/component tests; API contracts go to request-only tests; timing goes to benchmarks.** Real backend (local stack) for the ~20 journeys where mocks hide bugs; mocks only for failure injection.

### Tier B — Reader resilience (`e2e/resilience/`, every PR, Chromium) ~22
One browser test per *distinct failure class*; permutations become unit tests on the startup/identity reducers with fake clocks.
1. Cached page + tree paint before identity resolves
2. Changed account discards prior cache before store opens
3. Session denial / sign-out clears remembered content (incl. other tab)
4. Transient identity outage keeps remembered content
5. Manifest SWR: fresh reuse · expired revalidate without blanking · failed refresh keeps snapshot
6. Stale body hot-swaps without scroll reset
7. Slow/failed body → retry; offline → reconnect retries
8. Navigation during identity/store startup lands on requested page
9. Persistent storage unavailable → still reads/navigates/reloads; public vs session stay separate
10. Worker/leader failure → single recovery screen, no reload loop
11. Chunk-load failure → one reload then recovery screen (app-recovery)
12. Prefetch never blocks navigation; pauses on save-data/hidden
13. Hover/focus intent warms, brief hover/external links don't
14. Cold-load paints additively (no blanking) on 3 representative routes (replaces additive-paint + 17 visual-stability)
15. Large tree: every file reachable by keyboard
16. Shortcut survives refresh before scripts load (Cmd+K, `/`)
17. Public vs session scope switch preserves route
18. Multi-site: same slug cold/warm isolated (store ids, cache)
19–22. Two-tab leader handoff · stale worker version · public refresh doesn't restart store · unavailable page offers sign-in with destination

### Tier C — Contracts (`e2e/contract/`, request-only, no browser, every PR) ~15
One matrix-driven spec replacing `backend-api`, `multi-site-isolation` API invariants, `auth-gate-security`, `parity-e2e/security`, `preview-e2e/auth-gate`, `sidebar-pdfs` API half:
- route × auth-state table: anonymous / forged cookie / gate cookie / session → expected status + `cache-control`
- host → site resolution, injected headers overwritten, unknown host fails closed
- `/api/file`: 400s, traversal, extension allowlist, byte-range PDF
- manifest/search/tools/download are site-scoped and PII-redacted
- AI search/chat routes validate input without credentials
- liveblocks-auth/users/delete-thread param validation

### Tier D — Visual (`e2e/visual/`, macOS CI) 5
desktop shell · mobile shell · palette light/dark · landing · one overflow sweep across every public route at 360/768/1280 (replaces ~25 per-page width tests).

### Tier E — Deployed smoke (post-deploy, against preview/prod) ~8
anonymous root + deep link → gate, uncached · gate cookie → page renders from configured backend · client-rendered doc retains gate · cold start: Search + Ask wiki + Sign in open in place · theme persists · early shortcut after refresh · PDF range · session survives deploy.

### Moved out of Playwright
- Reducer/state tests for startup, identity, cache-retirement permutations → `src/**/*.test.ts` (fake timers).
- `visual-observer`, `paint-monitor`, `visual-runtime`, devtools footer → unit/component.
- Latency budgets, chat perf, table perf → `scripts/profile-*.ts`, run nightly with thresholds.
- CSS geometry (table fade edge, column-resize widths, palette geometry/typography) → component tests or the visual tier.

### Retire
`parity-e2e/` (after confirming cutover is complete), `playwright.parity.config.ts`, `compare-parity.ts`, `header-shell.spec.ts`, `playwright.stability.config.ts` + `visual-stability*` + `additive-paint` (folded into Tier B #14), `comments-live` (folded into Tier A `comments`).

## 5. Rollout

1. **Close gaps first** (before culling): provide Convex/Liveblocks test env to CI (or run Tier A `access`/`comments` on the local stack), add the fake-model chat, add a publish→read round trip.
2. **Build the new tiers beside the old** and run both for a week; CI runtime and failures per file become the cull evidence.
3. **Delete in this order**: parity-e2e → dead/opt-in specs → duplicated auth-gate/palette/responsive tests → startup permutations (after the unit versions land).
4. Convert the 4 shards to Tier A+B+C (no sharding likely needed at ~100 tests); keep Tier D on macOS and Tier E post-deploy.

## Status (updated 2026-10-05): consolidation integrated

Decisions: parity suite dropped; authenticated journeys run on the local Convex stack in PR CI (no secrets).

Result: **~500 declared tests / ~700 expanded runs in 93 files -> 153 expanded runs in 29 files (+8 deployed smoke tests, run per project against a deployment)**. Full merged suite on the local stack: all green after one deflake (134 passed, 12 skipped for deployed-only or opt-in reasons) plus the restored tests below.

New layout (`apps/app/`):
- `e2e/journeys/`: access, read, find, admin, chat (fake model), imaging, pii (real backend on the local stack); clinical-tools, comments, markdown, navigation, palette, public, search, tables, pathology (mocked).
- `e2e/resilience/`: identity-cache (14), runtime (12).
- `e2e/contract/`: request-only API/security/role matrix. `e2e/visual/`: 5 screenshot tests + overflow sweep. `e2e/live/`: opt-in Liveblocks and real-model tests. `deployed-e2e/`: post-deploy smoke (replaces preview-e2e and production-e2e).
- Local-stack CI step runs the real-backend journeys + contract; mocked specs run in the deployed shards.

Closed gaps: real sign-in/role/sign-out journeys in CI, admin role changes and bulk actions, chat send/stream/Stop/queue/error-retry without a real model (`WIKI_CHAT_FAKE_MODEL=1`), raw-PII route for admin vs non-admin, role/tag access on the local stack.

Still open (genuinely unique coverage dropped, decide whether to restore):
- OPFS fast-path guard/journal tests (store-fast-path, 4 tests, all passing before the cull).
- Fresh-page 403 clears remembered access with an unchanged content hash (security-relevant; best as a unit test).
- Stalled session body 30s recovery; compressed-snapshot restore for oversized vaults; invalid CSR payload fallback; build-keyed lazy-chunk reload guard (unit-test candidates).
- DICOM annotation save failure: the product never renders `setSaveStatus("error")`, so there is nothing to assert.
- Mobile touch pan/zoom (CDP), pathology save landing on the right slide after navigation, image theater across a manifest refresh, print layout, landing role-preview/PII demos, reader<->terms same-document navigation, non-Diana PII patterns and two-site isolation (local stack has only `diana`).
- Comments create/reply/resolve still need a Liveblocks dev key (nightly, `e2e/live/`).

Suspected product regressions surfaced by red-on-main tests (not verified): the cold load fetches the page body and manifest twice; the public store restarts on a public identity refresh; the early-reader to live handoff drops palette state; an upstream-added page is not searchable after the cached hot-swap. The new resilience specs avoid exact request counts, so they will not catch a fix or a worsening of the duplicate fetch.
