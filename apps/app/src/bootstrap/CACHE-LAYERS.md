# Reader cache layers

What the reader can paint from before (or instead of) the network, in the
order startup consults it. LiveStore is the only authoritative local copy;
every other layer is a presentation shortcut that LiveStore sync re-validates
(`src/sync/sync-controller.ts`). Paths are relative to `apps/app` unless they
start with `packages/`.

Versions come from `WIKI_READER_CACHE_GENERATIONS` in
`packages/wiki-content/src/index.ts`: `WIKI_READER_CACHE_VERSION` (now
`reader-v4`), `WIKI_PREVIOUS_READER_CACHE_VERSION` (`reader-v3`) and
`WIKI_READER_SCHEMA_VERSION`. Identity keys use `WIKI_SESSION_CACHE_VERSION`
(`v1`). Bumping the reader generation retires every layer below except the
HTTP cache, which needs no retirement.

| Layer | Holds | Written | Read | Versioned by | Retired |
| --- | --- | --- | --- | --- | --- |
| **Inlined payload** (in the HTML response, not persisted) | `<script id="wiki-page-bootstrap">` (one page) and `<script id="wiki-navigation-bootstrap">` (tree slice), each stamped `data-received-at` by the browser | `server/page-bootstrap.ts` (`injectPageBootstrap`, `sessionPageBootstrapScripts`, `navigationBootstrapScripts`), called from `server/app-shell.ts`; public pages only when non-sensitive, session pages only in a `private, no-store` response | `src/bootstrap/initial-reader-data.ts` (`readInitialReaderData`, first paint), `src/bootstrap/public-identity.ts`, `src/reader-session-prefetch.ts`; seeded into LiveStore by `src/bootstrap/seed-page.ts` (`seedInitialPage`) | `version` (1 public, 2 session) + `readerVersion === WIKI_READER_CACHE_VERSION`, origin, pathname, site slug; session payload must match the store's `cacheKey`/`userHash` (`src/bootstrap/page-payload.ts`) | Usable for `BOOTSTRAP_MAX_AGE_MS` (60 s) after receipt; the nodes are removed once seeded (`seed-page.ts`) and on an auth change (`src/WikiViteRoot.tsx`); `?readerBootstrap=0` ignores them |
| **localStorage startup snapshot** | `StartupSnapshot`: identity, manifest, up to 8 page bodies; gzip+base64 (`gz1:`) | `src/bootstrap/ReaderStartupCacheWriter.tsx` (lazy, mounted by `src/livestore/StoreHost.tsx`), from LiveStore queries after a validated manifest, on idle; write gating in `startup-cache-write-policy.ts`, encode in `encode-startup-cache.ts`, store in `writeStartupSnapshot` (`reader-startup-cache.ts`), which also sets the reader-shell cookie (`reader-shell-hint.ts`) | `readStartupSnapshot` in `src/bootstrap/reader-startup-cache.ts`, from `src/WikiViteRoot.tsx` (cached first paint); copied into an empty store by `src/bootstrap/seed-startup-cache.ts` | Key `wiki-vite:startup:<WIKI_READER_CACHE_VERSION>:<origin>\|<apiOrigin>` (`startup-cache-lifecycle.ts`); payload `version: 1`, `readerVersion`, partition, identity `cacheVersion`, account tag meta; max 2 MiB stored / 16 MiB decoded, 7-day age (`STARTUP_CACHE_MAX_AGE`) | `clearStartupSnapshot` (`startup-cache-lifecycle.ts`) removes the key, rotates `wiki-vite:startup-epoch` (other tabs reset on the `storage` event, and stale writers stop) and clears the cookie. Called on sign-in/sign-out (`src/shell/Header.tsx`), the auth-change window event and identity mismatch or denial (`src/WikiViteRoot.tsx`), an auth error during sync (`sync-controller.ts`), and on `/login` responses (`src/main.tsx`). A failed write removes it (`ReaderStartupCacheWriter.tsx`); `?readerCache=0` ignores it |
| **First-frame HTML snapshot** (retired) | Sanitized HTML of the rendered shell, one per origin | Nothing: `persistSafeSnapshot` (`src/livestore/snapshot-html.ts`) has no caller | Nothing in boot: `readFirstFrameSnapshot*` (`src/livestore/first-frame-snapshot.ts`) is used only by its tests; `dismissFirstFrameSnapshot` still removes a `#wiki-first-frame-snapshot` node if one exists (`StoreHost.tsx`, `StoreStartupRecovery.tsx`, `AppErrorBoundary.tsx`) | Key `wiki-vite:first-frame:<readerVersion>:<origin>` plus `readerCacheVersion`/`validatedAt` in the value | `src/main.tsx` deletes every `wiki-vite:first-frame:*` key on each load. Remaining code is dead and can be deleted with its tests |
| **OPFS fast-path image** | The LiveStore state SQLite file, read directly on the page thread instead of waiting for the leader worker to export it | By the LiveStore leader worker (it *is* the LiveStore state database; no separate copy) | `makeFastPathSnapshotReader` / `readGuardedSnapshot` in `src/livestore/fast-path-snapshot.ts`, passed as `experimental.fastPathSnapshot` to the patched adapter (`patches/@livestore%2Fadapter-web@0.3.1.patch`) in `StoreHost.tsx`; returns an image only when no journal exists and two reads match, else the leader snapshot is used | Same as LiveStore: directory `livestore-<storeId>@<liveStoreStorageFormatVersion>`, file `state<schemaHash>.db` | Same as LiveStore (it is the same file) |
| **LiveStore** (authoritative local copy) | Event log + state DB (`src/livestore/schema.ts`): site state, page index, page bodies, tree, assets | `src/sync/sync-controller.ts` (manifest + current route), `src/sync/BackgroundPrefetch.tsx` (ranked pages), seeding from the two layers above (`seed-page.ts`, `seed-startup-cache.ts`) | Every reader query (`src/livestore/queries.ts`); booted by `StoreHost.tsx` with OPFS, or the in-memory adapter when OPFS or Web Storage is unavailable (`src/livestore/reader-storage.ts`) | `storeId` from `makeWikiStoreId` (`packages/wiki-content/src/index.ts`): reader cache version, site, scope, origin, identity `cacheKey`; `siteState.schemaVersion === WIKI_READER_SCHEMA_VERSION` (`isCurrentReaderManifestValidated`); LiveStore's schema hash names the state file | `src/livestore/cache-retirement.ts`: previous-generation public store deleted once the current one is hydrated (`ReaderCacheRetirement.tsx`); session stores wiped on sign-out (`shutDownAndWipeReaderStores`, called from `Header.tsx`) with a retry flag `wiki-vite:clear-session-cache:<site>` honored by `SessionCacheRetirement.tsx`; `cacheResetRequested` event on auth errors (`sync-controller.ts`) and from the devtools footer / command palette |
| **HTTP cache, content-addressed `?v=`** | Page-batch and file responses whose URL names the content hash | Browser HTTP cache. Client adds `?v=`: `fetchPages({ versions })` in `packages/wiki-content/src/index.ts` (used by `sync-controller.ts` unless forced, and `BackgroundPrefetch.tsx`), `versionedFileUrl` in `src/wiki-assets.ts` for images/files. Server grants `private, max-age=31536000, immutable` only when `v` matches what this requester may read now: pages in `packages/wiki-content/src/server.ts` (`parseVersions`, `versionedCacheHeaders`), files in `server/api/files.ts`, gated sites in `server/api/gate.ts` (`X-Wiki-Version: match`) | Browser, on the next request for the same URL | The URL itself: a content change is a new URL; mismatches get the ordinary uncached answer | Never stale, so no expiry logic. Sign-out sends `Clear-Site-Data: "cache"` (`server/api/auth.ts`); forced reads (retry, startup-snapshot revalidation) omit `v` |

Related, not content: the public identity is kept under
`wiki-vite-public-identity:<WIKI_SESSION_CACHE_VERSION>:<partition>`
(`src/public-identity.ts`, written by `src/WikiViteRoot.tsx`) so a
signed-out reader can boot offline.
